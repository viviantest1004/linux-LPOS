A small Linux distribution, written from scratch

커널 설정부터 C 라이브러리, init, 셸, 130개 명령어까지 전부 Claude Code가 썼습니다. 사람이 검토한 코드가 아닙니다 — 아래 쓰기 전에 알아둘 것을 꼭 읽어주세요.

이게 뭔가요What this is

512MB 램짜리 라즈베리파이 제로 2 W 한 대에 우분투를 올렸더니 아무것도 하기 전에 램의 절반이 사라져서, 그게 아까워서 만들기 시작한 배포판입니다. 만들다 보니 그 보드에만 매인 구석이 없어서 지금은 arm64 가상머신과 amd64 PC에서도 그대로 돕니다.

시스템 전체가 커널 이미지 파일 하나이고, 부팅하면 램으로 풀립니다. 디스크 위의 어떤 것도 돌아가는 시스템의 일부가 아니라서, 전원을 갑자기 뽑아도 다음 부팅은 항상 멀쩡합니다.

받은 뒤에After you download

먼저 파일이 온전한지 확인하세요. 받다가 끊긴 이미지는 부팅 도중에 이상하게 실패합니다.

sha256sum -c SHA256SUMS.txt

SD카드에 굽기 — /dev/sdX를 꼭 확인하세요. 여기서 재부팅으로 되돌릴 수 없는 실수는 이것 하나뿐입니다.

xz -d < @PI_NAME@ | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

첫 부팅에서 /data 파티션이 카드 전체로 알아서 늘어납니다.

가상머신 — 압축을 풀고 디스크로 붙인 뒤 UEFI 부팅으로 설정하세요. MBR 부트스트랩은 일부러 비워두었기 때문에 legacy BIOS로는 뜨지 않습니다. 이미지 파일을 truncate -s 16G 하면 디스크가 커지고, 파일은 sparse라 실제로 쓰는 만큼만 차지합니다.

SSH — 비밀번호 로그인은 아예 컴파일하지 않았습니다. 인터넷에 물린 보드에서 비밀번호는 시간 문제라, 선택지로 두지 않았습니다. 카드의 첫 번째 파티션은 FAT32라 윈도우·맥·리눅스 어디서나 열리니, 거기 authorized_keys에 공개키를 넣으세요. 사용자는 root 하나입니다.

cat ~/.ssh/id_ed25519.pub >> /media/BOOT/authorized_keys

안에서 할 수 있는 것What you get once it boots

  • SSH 로 들어가기가 쉬워졌습니다. authkey new 하나면 기기에서 키를 만들고, 등록하고, 개인키를 가져갈 자리에 두고, 이 기계의 실제 주소가 들어간 접속 명령줄을 그대로 출력합니다. 비밀번호 인증은 여전히 컴파일하지 않았습니다.
  • 서버로 쓸 수 있습니다. httpd 로 디렉터리를 HTTP 로 서비스하고, service add httpd 로 등록하면 init 이 지킵니다 — 죽으면 다시 뜨고, 재부팅해도 남고, 메모리가 모자라도 guard 가 죽이지 않습니다. 포트는 firewall allow 8080 으로 기기에서 바로 엽니다.
  • 데비안 패키지가 됩니다. apt install ripgrep htop — 진짜 데비안 apt입니다. 데비안 유저랜드가 /data/debian에 따로 들어가므로 시스템 이미지는 손대지 않고, rm -rf /data/debian 하면 전부 되돌아갑니다. 처음 한 번은 95MB를 받아 440MB로 풉니다.
  • 파이썬과 pip가 그대로 됩니다. CPython 3.12에 glibc가 같이 들어 있어서 numpy·pillow 같은 C 확장 휠도 설치됩니다. 일반 리눅스 바이너리도 run으로 돕니다 (arm64와 amd64 양쪽 다).
  • USB 드라이브를 꽂으면 알아서 붙습니다. /media/<이름>에 마운트되고, 계속 쓸 드라이브는 storage adopt로 고정하면 재부팅을 넘겨 같은 자리에 있습니다. 장치 이름이 아니라 파일시스템 레이블로 찾기 때문에 포트를 바꿔 꽂아도 됩니다.
  • 혼자 안 죽게 만들어 두었습니다. guard가 메모리·온도·전압· CPU를 지켜보다가 포크 폭탄과 메모리 고갈을 정리하고, 워치독이 커널이 멈추면 보드를 재시작하고, 부팅 실패가 다섯 번 이어지면 사용자 스크립트를 건너뜁니다.

쓰기 전에 알아둘 것Before you rely on this

지원되는 제품이 아니라 취미로 만든 운영체제입니다. 보안팀도, CVE 절차도, 대기하는 사람도 없습니다. 계속 돌아가야만 하는 일에는 Raspberry Pi OS Lite나 데비안을 쓰세요.
  • 사람이 아니라 Claude Code가 썼습니다. 설계와 디버깅 과정이 커밋 기록과 주석에 전부 남아 있지만, 독립적인 엔지니어의 검토를 받은 적이 없고 실제 운영에 쓰인 적도 없습니다.
  • 실기기 검증이 아직입니다. 전부 QEMU에서 시험했습니다. 라즈베리파이 실물에서의 WiFi, 온도 센서, 하드웨어 워치독, 실제 SD카드에서의 EMMC 드라이버는 확인하지 못했습니다.
  • 보안 부분은 외부 감사를 받지 않았습니다. 업데이트 서명 검증, 방화벽, DNS·NTP 위조 방지가 구현돼 있고 근거도 주석에 적혀 있지만, 다른 사람이 검토한 적은 없습니다. 이것만 믿고 적대적인 망에 바로 올리지 마세요.
  • 재부팅을 넘겨 남는 곳은 /data 하나이고, 그건 카드 한 장의 파티션 하나입니다. 카드는 죽습니다. 아까운 것은 따로 받아두세요.
  • GUI가 없고 컨테이너를 돌리지 않습니다. DRM 드라이버는 커널에 있지만 X11/Wayland는 직접 올려야 하고, cgroup·네임스페이스는 컨테이너 용도로 켜두지 않았습니다.
  • 거친 구석이 남아 있고, 대개 조용한 쪽입니다. 최근 사례: echo x | grep x 가 셸이 존재한 내내 "command not found" 였고, cmd ; echo $? 는 항상 0이었고, 127.0.0.1 은 루프백 인터페이스가 올라오지 않아 통하지 않았습니다. 전부 고쳤고 각각 셀프테스트에 검사가 생겼지만, 이런 것이 더 나올 거라고 보시는 편이 맞습니다.

확인된 것: 두 아키텍처 모두 QEMU 실제 부팅에서 프로젝트 셀프테스트를 실패 없이 통과합니다 — 부팅, 저장소, SSH, 파이썬, 외부 바이너리, 그래픽, 보안, 오류 경로, 리다이렉션, 로깅, 시간, 새 명령어들, 셸 문법까지. 따로: 포크 폭탄이 한 번의 패스로 정리되고 init·SSH·로그가 살아 있으며, 메모리 고갈은 원인이 된 프로세스만 죽이고, apt 가 데비안 패키지를 받아 설치하고 실행합니다.

English

A small Linux distribution written from scratch — kernel configuration, C library, init, shell and 130 commands, all of it written by Claude Code, Anthropic's coding agent, working under the repository owner's direction. No human wrote or reviewed this code. Please read the warnings below before trusting it with anything.

It started because a Raspberry Pi Zero 2 W has 512MB of RAM and Ubuntu spends half of it before you have done anything. Nothing in it turned out to be specific to that board, so it now runs on arm64 virtual machines and amd64 PCs as well. The whole system is a single kernel image, 13–22MB, unpacked into RAM at boot — nothing on disk is part of the running system, so pulling the power leaves nothing to corrupt.

Which image. The first is a Raspberry Pi Zero 2 W image that also runs in arm64 virtual machines — it carries both an uncompressed kernel for the Pi's GPU and an EFI executable for UEFI. The second is for ordinary PCs and desktop VMs. The third is a ready-made UTM bundle for arm64 VMs only, and will not boot on the board.

Check what you downloaded with sha256sum -c SHA256SUMS.txt; a truncated image fails in confusing ways halfway through boot. Burn a card with xz -d < image.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync, checking /dev/sdX twice — that is the one mistake here a reboot cannot undo. In a VM, set UEFI boot; the MBR bootstrap is empty on purpose.

SSH has no passwords. Password authentication is not compiled in — on a board facing the internet a password is a matter of time, so it was not offered as an option. Put your public key in authorized_keys on the card's first partition, which is FAT32 and opens on any PC. There is one user, root.

Once it boots you get sed, awk, grep and diff over one shared regular expression engine; real Debian packages through apt install, into a separate tree under /data/debian so removing it undoes everything; CPython 3.12 with pip and working manylinux wheels; USB drives that mount themselves and can be pinned across reboots by filesystem label; httpd to serve a directory, supervised by init once you service add it; firewall allow 8080 to open a port without a card reader; and authkey new, which makes a key on the machine and prints the exact ssh command to get in with.

This is a hobby operating system, not a supported product. No security team, no CVE process, nobody on call. Real Pi hardware is not verified — everything was tested in QEMU, so WiFi, the thermal sensors, the hardware watchdog and the EMMC driver against a real card are all unconfirmed. The security work has not been audited by anyone. For anything that has to keep working, use Raspberry Pi OS Lite or Debian.

What is verified: both architectures pass the project's self-test with nothing failing, on real QEMU boots. Separately: a fork bomb is cleared in one sweep with init, SSH and the log still running; memory exhaustion kills the process that caused it and nothing else; and apt fetches, installs and runs a Debian package. Full source, documented in English and Korean, at @REPO_SHORT@. MIT licensed.
