# Raspberry Pi Zero 2 W 하드웨어 참조

## SoC

| 항목 | 값 |
|---|---|
| SoC | BCM2710A1 (RP3A0 패키지 — SoC + RAM 을 한 패키지에) |
| CPU | Cortex-A53 ×4, ARMv8-A, 1.0 GHz |
| 캐시 | L1 32KB I + 32KB D (코어당), L2 512KB (공유) |
| RAM | **512MB LPDDR2** ← 이 보드의 핵심 제약 |
| GPU | VideoCore IV @ 400MHz |
| 무선 | CYW43438 — WiFi 2.4GHz b/g/n + BT 4.2 BLE |
| 저장 | microSD (SDIO) |
| USB | micro-USB OTG ×1 |
| 영상 | mini HDMI, CSI-2 카메라 커넥터 |

Pi 3 와 같은 BCM2837 계열이라 **페리페럴 베이스가 `0x3F000000`** 이다.
Pi 4 코드(`0xFE000000`)나 Pi 1 코드(`0x20000000`)를 그대로 가져오면 안 된다.

## 메모리 맵 (ARM 물리 주소)

| 주소 | 블록 |
|---|---|
| `0x00000000` | SDRAM 시작 |
| `0x00000080`~`0x000000FF` | 펌웨어 스핀테이블 (보조 코어 릴리즈용) |
| `0x00080000` | **커널 로드 주소 (kernel8.img)** |
| `0x3F003000` | 시스템 타이머 (1MHz) |
| `0x3F00B200` | 인터럽트 컨트롤러 |
| `0x3F00B880` | VideoCore 메일박스 |
| `0x3F100000` | 파워매니지먼트 / 워치독 |
| `0x3F200000` | GPIO |
| `0x3F201000` | PL011 UART0 |
| `0x3F215000` | AUX (미니 UART, SPI1/2) |
| `0x3F300000` | EMMC (SD카드) |
| `0x40000000` | ARM 로컬 (코어별 타이머/메일박스) |

데이터시트(BCM2835 ARM Peripherals)는 VideoCore 버스 주소 `0x7Exxxxxx`
로 적혀 있다. ARM 물리 주소로 바꾸려면 `0x7E` → `0x3F` 로 치환한다.

## 전원 — 5V 가 맞다

전원과 신호는 전혀 다른 얘기다. 헷갈리기 쉬우니 정리해둔다.

| 위치 | 전압 | 비고 |
|---|---|---|
| 마이크로 USB `PWR IN` | **5V** ✅ | 설계상 5V 를 넣는 자리 |
| 40핀 헤더 2·4번 핀 | 5V ✅ | 5V 출력 |
| 40핀 헤더 1·17번 핀 | 3.3V ✅ | 3.3V 출력 |
| **GPIO 신호 핀** (14, 15 등) | **3.3V 만** ❌ | 5V 를 넣으면 손상된다 |

5V 는 보드의 레귤레이터를 거쳐 3.3V 로 낮아진 뒤 SoC 로 간다. 반면
GPIO 는 SoC 의 3.3V I/O 에 직결되어 있고 중간에 보호가 없다.
**5V 는 전원에는 맞고 신호에는 틀리다.**

### 포트 위치

Pi Zero 2 W 는 마이크로 USB 가 두 개다. 미니 HDMI 쪽부터:

```
[미니 HDMI]   [USB]        [PWR IN]
              데이터(OTG)   전원  <- 여기에 5V
```

보드에 `USB` / `PWR IN` 이 인쇄되어 있다.

### 사양

- **5V 2.5A 권장.** 실제 소비는 유휴 약 350mA, 부하 시 1A 근처.
- 전압이 처지는 값싼 충전기를 쓰면 랜덤 리부팅과 SD 손상이 난다.
  라즈베리파이의 이상 동작 중 상당수가 실은 전원 문제다.

### 전원을 두 군데서 넣지 않는다

마이크로 USB 로 전원을 넣으면서 시리얼 어댑터의 5V 를 헤더 5V 핀에도
연결하면 두 전원이 서로를 밀어낸다(역전류). 헤더 5V 핀으로 넣는 것은
입력단 보호도 우회한다.

전원은 마이크로 USB 하나로만 넣고, 시리얼 어댑터는 `GND` 와 `TX`
(필요하면 `RX`)만 연결한다.

## 시리얼 콘솔 배선 (필수)

베어메탈 개발에서 시리얼은 눈이다. USB-TTL 어댑터가 하나 필요하다.

### ⚠️ 반드시 3.3V. 5V 는 보드를 죽인다

라즈베리파이 GPIO 는 3.3V 로직이고 **5V 내성이 없다**(not 5V tolerant).
절대 최대 정격이 3.3V + 0.5V 수준이라 5V 가 걸리면 핀이나 SoC 가 손상된다.

위험한 방향은 하나뿐이다:

```
어댑터 TX ──→ Pi GPIO15 (RX)   ← Pi 의 "입력". 여기에 5V 가 걸리면 죽는다
Pi GPIO14 (TX) ──→ 어댑터 RX   ← 이쪽은 보통 안전
                                 (5V TTL 입력의 HIGH 문턱이 대개 2.0V 라
                                  3.3V 를 HIGH 로 읽는다)
```

### 전압을 몰라도 되는 방법 (가장 간단)

**부팅 로그를 보기만 할 거라면 2선만 연결한다.**

```
Pi 8번 핀 (GPIO14 TX) ──→ 어댑터 RX
Pi 6번 핀 (GND)       ──→ 어댑터 GND

어댑터 TX 는 연결하지 않는다        ← 핵심
```

어댑터 TX 를 꽂지 않으면 어댑터가 Pi 로 전압을 밀어넣을 경로 자체가
없다. 어댑터가 5V 든 3.3V 든 무관하게 안전하다.

이 상태로 부팅 로그는 전부 볼 수 있다. 못 하는 것은 시리얼 모니터에
명령을 타이핑하는 것뿐이다.

명령 입력까지 하려면 어댑터 TX 를 Pi GPIO15 에 연결해야 하고,
그때부터 전압이 문제가 된다.

**구분하는 법**

1. **멀티미터로 재기 — 이게 확실하다.**
   어댑터만 USB 에 꽂고 아무것도 연결하지 않은 상태에서 TX 핀과 GND 사이
   전압을 잰다. 유휴 TX 는 HIGH 이므로:
   - 약 3.3V → 3.3V 로직 ✅
   - 약 5.0V → 5V 로직 ❌

2. **점퍼/스위치 확인.** `3V3` / `5V` 표시가 있으면 3.3V 로 놓는다.
   단, 값싼 CH340 보드 중에는 **그 점퍼가 VCC 출력 핀만 바꾸고 신호
   레벨은 5V 그대로**인 것이 있다. FT232RL 의 VCCIO 점퍼는 신호 레벨도
   같이 바뀌지만 보드마다 다르다. 그래서 1번이 확실하다.

3. **멀티미터가 없으면 보이는 것으로 추정한다.** 다만 확실하지 않다.

   | 확인할 것 | 판단 |
   |---|---|
   | `3V3` / `5V` 점퍼나 스위치 | 3.3V 쪽으로 놓는다 |
   | 보드에 `3.3V` 만 인쇄 | 3.3V 일 가능성이 높다 |
   | 아무 표시 없음 | **5V 로 가정한다** |
   | 구매처 상세 설명 | "3.3V" 명시가 있으면 신뢰할 만하다 |

4. **애초에 안전한 것을 산다.** "3.3V" 로 명시된 것, 또는 라즈베리파이용
   USB 디버그 케이블.

5. **애매하면 그냥 분압 저항을 단다.** 어댑터 TX 쪽에만 넣으면 된다.
   5V 어댑터든 3.3V 어댑터든 양쪽 다 안전해진다 — 3.3V 에 달아도
   2.2V 가 나와 Pi 가 HIGH 로 읽는다. 판별하느라 고민할 바에 다는 편이 낫다.
   ```
   어댑터 TX ──[ 1kΩ ]──┬── Pi GPIO15 (RX)
                        │
                      [ 2kΩ ]
                        │
                       GND        5V x 2/(1+2) = 3.33V
   ```

### 어댑터의 5V/VCC 핀은 연결하지 않는다

**`GND`, `TX`, `RX` 3선만** 쓴다. Pi 전원은 따로 USB 로 넣는다.
양쪽에서 전원을 넣으면 역전류(backfeed)로 문제가 생긴다.

```
   Pi Zero 2 W 40핀 헤더 (USB 포트가 아래로 오게 놓고 봤을 때)

   핀 1  ┌─┬─┐  핀 2   (5V)
         │ │ │
   핀 5  ├─┼─┤  핀 6   GND         ──→ 어댑터 GND
   핀 7  ├─┼─┤  핀 8   GPIO14 TXD0 ──→ 어댑터 RX   (교차!)
   핀 9  ├─┼─┤  핀 10  GPIO15 RXD0 ──→ 어댑터 TX   (교차!)
```

터미널:
```bash
screen /dev/ttyUSB0 115200        # 종료: Ctrl-A 다음 K
# 또는
picocom -b 115200 /dev/ttyUSB0    # 종료: Ctrl-A 다음 Ctrl-X
minicom -D /dev/ttyUSB0 -b 115200
```

설정은 **115200 8N1, 흐름제어 없음**.

## microSD 카드 고르기

비싼 카드를 사도 이득이 없다. 이유가 분명하다.

### Zero 2 W 는 25MB/s 가 천장이다

Pi 의 SD 컨트롤러는 **SDR25** 까지만 지원한다. UHS-I 의 고속 모드
(SDR50/SDR104)를 쓰지 못한다. 200MB/s 짜리 카드를 꽂아도 25MB/s 로 돈다.

| 항목 | 권장 | 이유 |
|---|---|---|
| 형태 | **microSD** | full-size 는 안 들어간다 |
| 용량 | **16~32GB** | 우리 이미지가 256MB 라 8GB 도 남는다 |
| 타입 | **SDHC** (32GB 이하) | SDXC 도 되지만 이점이 없다 |
| 속도 | **Class 10 / U1** | 이 이상은 낭비 (25MB/s 천장) |
| 앱 등급 | **A1** | 아래 참조 |
| 브랜드 | SanDisk, Samsung | 가짜가 많다 |

구체적으로는 SanDisk Ultra microSDHC 32GB A1 이나 Samsung EVO Plus 32GB.

### A2 를 사지 않는 이유

A2 는 **CQHCI**(커맨드 큐잉) 하드웨어가 있어야 제 성능이 난다.
Pi 중에서는 BCM2712(Pi 5)만 그 엔진을 갖고 있고, 그마저도 커널 지원이
없다. Zero 2 W 는 해당 사항이 아예 없다.

A2 카드는 CQ 명령을 받지 못하면 A1 속도를 보장할 의무가 없어서, 오히려
A1 보다 느린 경우도 보고된다. **A1 이 싸고 확실하다.**

### 우리 설계에서는 카드 수명 걱정이 거의 없다

루트가 커널에 내장된 initramfs(RAM)라 SD 에 쓰기가 거의 없다.
`/data` 파티션에만 가끔 쓴다. 그래서 "High Endurance" 같은 비싼 카드도
필요 없고, 전원을 갑자기 뽑아도 루트가 깨지지 않는다.

### 굽기

```bash
sudo dd if=sdcard/lp-zero.img of=/dev/sdX bs=4M conv=fsync status=progress
```

카드에 원래 어떤 파일시스템이 있었는지는 상관없다. 이미지가 자기
MBR 과 파티션을 통째로 덮어쓴다.

굽고 나면 이렇게 된다:

```
p1  FAT32   64MiB   부트 (GPU 블롭, 커널, DTB, config.txt)
p2  ext4   188MiB   데이터 (wpa_supplicant.conf, SSH 호스트키, 파일)
나머지                미할당 - 필요하면 나중에 p2 를 늘린다
```

### ⚠️ 윈도우에 꽂았을 때 "포맷하시겠습니까" 를 누르지 말 것

윈도우는 ext4 를 읽지 못한다. SD 카드를 꽂으면 부트 파티션(FAT32)만
드라이브 문자로 뜨고, 데이터 파티션(ext4)에 대해서는

> "X: 드라이브의 디스크를 사용하려면 먼저 포맷해야 합니다"

라는 팝업이 뜬다. **고장난 것이 아니라 윈도우가 그 형식을 모를 뿐이다.**
"디스크 포맷" 을 누르면 데이터 파티션이 날아간다. **취소** 를 누른다.

### 파티션이 폴더처럼 보이는 이유

윈도우는 파티션마다 드라이브 문자를 붙여 따로 보여준다. 리눅스와 맥은
파티션을 **하나의 디렉터리 나무에 붙인다(mount)**. 그래서 폴더처럼
보이지만 실제로는 다른 저장장치다.

```
/                      initramfs (RAM)
├── bin, etc, dev      전부 RAM
└── data               <- SD 카드의 2번 파티션 (ext4)
```

`/etc/rc` 의 이 줄이 그 연결을 만든다:

```
mount /dev/mmcblk0p2 /data
```

`mmcblk0p2` = mmc 블록장치 0번의 파티션 2.

"리눅스는 파티션이 하나" 라는 인상은 이 마운트 방식 때문에 생긴다.
실제로는 윈도우도 맥도 리눅스도 모두 여러 파티션을 쓴다. 특히 맥은
Catalina 부터 시스템 볼륨을 읽기 전용으로 분리했는데, 전원이 갑자기
끊겨도 시스템이 깨지지 않게 하려는 것으로 우리 설계와 같은 발상이다.

## 화면 (미니 HDMI)

Zero 2 W 는 **미니 HDMI** 단자다. 일반 HDMI 케이블이 안 들어가므로
미니HDMI→HDMI 케이블이나 어댑터가 필요하다.

프레임버퍼는 이미 동작하므로 전원과 HDMI 만 연결하면 부팅 화면과
로그를 볼 수 있다. 다만 **입력 장치가 없으므로 읽기 전용**이다 —
시리얼 모니터에 명령을 치려면 시리얼 케이블이 필요하다.

화면이 검게 나오면 `boot/config.txt` 의 `hdmi_force_hotplug=1` 주석을
푼다. 펌웨어는 부팅 시점의 핫플러그 신호로 모니터 유무를 판단하는데,
모니터를 나중에 켜거나 일부 KVM·캡처보드는 이 신호를 제대로 주지 않는다.

`gpu_mem` 은 최소 64 여야 프레임버퍼를 할당할 수 있다 (현재 설정값).

## 원격 접속은 리눅스가 올라간 뒤에

전원과 HDMI 만 연결하고 네트워크로 접속하는 방식(SSH 등)은 현재
펌웨어로는 불가능하다. 네트워크 스택이 없기 때문이다.

베어메탈에서 이걸 만들려면 SDIO 호스트 드라이버, CYW43438 펌웨어
업로드와 제어 프로토콜, 802.11 결합과 WPA2(AES·SHA1·PBKDF2·4-way
핸드셰이크), TCP/IP 스택, 그리고 SSH 서버(공개키 암호·키교환·HMAC)가
전부 필요하다. 이 프로젝트의 나머지를 다 합친 것보다 큰 작업이다.

리눅스가 부팅되면 커널 드라이버 + wpa_supplicant + dropbear 로
해결된다. **원격 접속이 목표라면 Phase 3(부트로더) → Phase 4(커널)를
먼저 하는 것이 순리다.**

## ACT LED

온보드 초록 LED 는 **GPIO 29** 에 물려 있다 (업스트림 디바이스트리
`bcm2710-rpi-zero-2-w.dts` 기준, active-low).

극성이 확실하지 않아도 우리 코드는 *토글*하므로 어느 쪽이든 깜빡인다.
시리얼이 안 잡힐 때 "펌웨어가 살아는 있는지" 확인하는 최후의 수단이다.

## 512MB 라는 제약

이 보드에서 가장 중요한 숫자다. `gpu_mem` 으로 GPU 에 떼어주는 만큼
ARM 이 잃는다.

| gpu_mem | ARM 가용 | 용도 |
|---|---|---|
| 16 | 496MB | 완전 헤드리스 |
| 64 | 448MB | 프레임버퍼 사용 (현재 설정) |
| 128 | 384MB | 하드웨어 비디오 디코딩 |

참고로 Raspberry Pi OS Lite 는 부팅 직후 90~120MB 를 쓴다.
우리가 직접 만들면 20~40MB 로 끝난다 — 이 차이가 512MB 에서는 크다.
